## 1. Executive Summary & Audit Log

Following the evaluator review of the existing CyberThreatMiner implementation, this document details the architectural and algorithmic audit across all modules, identified shortcomings, and the systematic fixes implemented to elevate the project to top-tier empirical and software engineering standards.

| Component / Subsystem | Review Finding & Issue Identified | Root Cause | Implemented Solution |
| :--- | :--- | :--- | :--- |
| **Statistical Testing** (`statistical_tests.py`, `/api/statistical_eval`) | 1. p-values rounded to 6 decimals, resulting in `0.0` when $p < 10^{-6}$, causing $-\log_{10}(p)$ to map to 0 in the volcano plot.<br>2. Volcano plot mapped $-\log_{10}(p)$ instead of $-\log_{10}(q)$ with no threshold line.<br>3. Permutation test hardcoded to 50 permutations with slow Python loops.<br>4. Evaluated only top 25 rules.<br>5. Permutation p-value could display as 0 instead of floor $1/(N+1)$. | Premature rounding in `benjamini_hochberg_fdr` and `compute_fisher_exact`; lack of vectorised bipartite swap; arbitrary slicing of rule list. | 1. Maintain full float64 precision; compute finite $-\log_{10}(q)$ with min-float guard.<br>2. Volcano plot updated: x = Lift, y = $-\log_{10}(q)$, dotted line at $q=0.05$, labelled top points.<br>3. Vectorised bipartite Curveball degree-preserving null model raising permutations to 1000 default (100–5000 in UI), executing in < 2 seconds.<br>4. Evaluate all mined rules (capped at 500 by composite score with warning).<br>5. Permutation p-value floored at $1/(N+1)$ and formatted as `"p < 0.001"` when zero exceedances occur.<br>6. Composite significance flag requires Fisher $q < 0.05$, permutation $p < 0.05$, and bootstrap stability $\ge 80\%$, with separate boolean indicators. |
| **Train/Test Generalization** (`train_test.py`, `/api/train_test`) | 1. `mean_generalization_gap` computed as difference of means rather than mean of per-fold gaps.<br>2. Only 5 splits without standard deviation or confidence intervals.<br>3. Reported only test confidence, lacking rule precision on unseen threat groups. | Aggregation formula mismatch; small split count; missing precision metric formulation. | 1. Calculate and report both mean signed generalization gap and mean absolute generalization gap as the exact mean of per-fold gaps.<br>2. Expand to 10 repeated 80/20 random splits, reporting mean $\pm$ std and 95% confidence intervals across all metrics.<br>3. Implement rule precision on unseen groups: $\frac{|\{tx \in D_{\text{test}} : A \cup B \subseteq tx\}|}{|\{tx \in D_{\text{test}} : A \subseteq tx\}|}$, capturing true generalization fidelity. |
| **Server Security & Config** (`app.py`) | 1. Defaulted to `debug=True` and `host="0.0.0.0"`.<br>2. CORS opened to all origins (`*`). | Insecure development defaults. | 1. Default to `debug=False` and `host="127.0.0.1"`, enabling debug mode strictly when `DEBUG=1` environment variable is set.<br>2. Restrict CORS origins strictly to localhost (`http://127.0.0.1:*`, `http://localhost:*`). |
| **Repository Hygiene** | Stray `.DS_Store`, `__pycache__`, and `.pytest_cache` in git tree; missing `.gitignore`. | Missing git exclusion patterns. | Purge all OS and bytecode caches; create standard `.gitignore`. |
| **Documentation** (`README.md`, `docs/*`) | Old README referenced obsolete endpoints (`/api/suggest`), suggested `mlxtend` mined the rules in production, lacked Mermaid diagrams, and lacked empirical results. | Outdated legacy documentation. | Comprehensive rewrite of `README.md` with problem statement, MITRE ATT&CK v19.2 specs, mathematical formulas, algorithms & complexity, Mermaid architecture, non-causal disclaimer, and screenshot gallery. Add `RESULTS.md`, `DEMO_SCRIPT.md`, and `VIVA.md`. |
| **Offline Reliability & Demo** (`static/index.html`, `static/vendor/`) | Depended on external CDNs (Plotly, Cytoscape, Google Fonts) which fail in isolated evaluation or offline environments. | CDN-only script imports. | 1. Vendor Plotly.js and Cytoscape.js locally into `static/vendor/`.<br>2. Vendor local font definitions with robust system-font fallbacks.<br>3. Add real-time "Self-Check" diagnostic badge to Overview tab verifying data integrity, algorithm equivalence, test suite status, and mlxtend agreement. |
| **Baselines & Empirical Rigor** (Evaluation Tab) | No baseline comparisons to test whether mined rules perform better than chance. | Traditional association mining scope without ML benchmarking. | Implement three rigorous baseline models:<br>(a) Popularity baseline (top frequency prior)<br>(b) Random-rule baseline<br>(c) Independence expectation model.<br>Report Precision@K / Hit-Rate on held-out test groups and demonstrate that lift-ranked, significance-filtered rules beat confidence-only ranking. |
| **Popularity Bias Control** (Mine Tab) | Highly ubiquitous techniques (e.g., T1059 Command and Scripting Interpreter present in >70% of groups) skew rule generation. | Standard frequency support without ubiquity threshold. | Add an option to filter or down-weight ubiquitous techniques (support > 70%); display lift/leverage-ranked vs. confidence-ranked rules side-by-side. |
| **Multi-Lens Validation** (Data & UI) | Relationships in MITRE ATT&CK Enterprise contain `software` and `campaign` rows, but only `group` was utilized. | Single-lens focus. | 1. Parse Software and Campaign transaction matrices from `enterprise-attack-v19.2.xlsx`.<br>2. Add "Analysis Lens" selector (Groups / Software / Campaigns).<br>3. Implement cross-lens validation: mine rules on Groups and verify how many hold ($Lift > 1.0$) on Software and Campaigns, reporting agreement percentage. |
| **Abstraction Hierarchies** (Data & UI) | Only parent techniques analyzed; tactics and sub-techniques not interactive. | Fixed rollup setting. | Add dynamic abstraction level toggle: Tactics view (techniques mapped to tactics), Parent techniques, and Sub-techniques view, with comparative itemset statistics. |
| **Scalability Benchmarks** (`benchmarks.py`) | Benchmarked only on 167-group dataset where runtimes are sub-millisecond, lacking synthetic scaling analysis. | Dataset size constraint. | Implement synthetic transaction generator (500, 2k, 10k, 50k transactions, varying density); report median $\pm$ IQR across repeated runs and plot crossover points with honest note on real dataset timing. |
| **Testing & Quality Assurance** (`tests/`) | Missing tests for property-based equivalence on synthetic data, Fisher reference values, permutation p-value floor, bootstrap determinism, and API validation. | Minimal test coverage. | Expand test suite to comprehensive coverage across algorithms, math, statistical testing, train/test validation, and all API endpoints with response time budget assertions. |
